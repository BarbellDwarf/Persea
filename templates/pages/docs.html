Getting Started

persea is a lightweight Rust replacement for the Apache Guacamole Java webapp. It proxies the Guacamole protocol over WebSockets between web browsers and guacd.

Quick Start

# Clone and build
git clone https://github.com/your-org/persea.git
cd persea
cargo build --release

# Run with config
./target/release/persea --config config.toml serve

Requirements

  • Rust 1.75+ (for building)
  • guacd (Apache guacamole-server) running on port 4822
  • SQLite database (auto-created)
  • Optional: Vault/OpenBao for connection storage
  • Optional: OIDC provider for SSO authentication

Docker

docker build -t persea .
docker run -p 8089:8089 persea

Configuration

persea uses a TOML configuration file. Key settings:

Core Settings

[server]
listen_addr = "0.0.0.0:8089"
guacd_addr = "127.0.0.1:4822"

[database]
db_path = "/opt/persea/data/persea.db"

[session]
max_duration_secs = 14400   # 4 hours
cleanup_delay_secs = 60

[recording]
path = "/opt/persea/recordings"
max_disk_percent = 80
max_recordings = 1000

TLS

[tls]
cert_path = "/etc/persea/cert.pem"
key_path = "/etc/persea/key.pem"
guacd_cert_path = "/etc/guacd/ca.pem"  # Optional

Vault Integration

[vault]
addr = "https://vault.example.com:8200"
mount = "secret"
base_path = "persea"
role_id = "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
# VAULT_SECRET_ID env var provides the secret ID

For multi-Vault DR deployments, see [vault_shared] and [vault_local] sections in the full config reference.

Authentication Methods

persea supports multiple authentication backends.

OIDC (OpenID Connect)

[oidc]
issuer_url = "https://auth.example.com"
client_id = "persea"
client_secret = "..."
redirect_uri = "https://persea.example.com/auth/callback"
groups_claim = "groups"

OIDC provides SSO with group-based role mapping via [admin.group_mappings].

Database (Password)

Local password authentication. Users are managed via the admin UI or CLI commands.

LDAP / RADIUS

External directory authentication. Configured via auth provider chain in [auth] section.

API Keys

API key authentication for programmatic access. Create via CLI: persea add-admin --name mykey.

TOTP (Two-Factor)

Optional TOTP 2FA. Users can enroll from the account settings page. Configure enforcement in [totp]:

[totp]
enabled = true
issuer = "persea"
enforcement = "All"   # Off | AdminsOnly | All

API Reference

All API endpoints require authentication unless noted. Responses are JSON.

Sessions

Method Path Description
POST/api/sessionsCreate a new session
GET/api/sessionsList active sessions
GET/api/sessions/{id}Get session details
DELETE/api/sessions/{id}Terminate session
PUT/api/sessions/{id}/thumbnailUpload session thumbnail
GET/api/sessions/{id}/thumbnailGet session thumbnail

Address Book

Method Path Description
GET/api/addressbook/foldersList all folders
POST/api/addressbook/foldersCreate folder
GET/api/addressbook/folders/{scope}/{folder}/entriesList entries in folder
POST/api/addressbook/folders/{scope}/{folder}/entriesCreate entry
POST/api/addressbook/folders/{scope}/{folder}/entries/{entry}/connectConnect to entry

Recordings

Method Path Description
GET/api/recordingsList recordings
GET/api/recordings/{name}Download recording
DELETE/api/recordings/{name}Delete recording

User Tokens (Self-Service)

Method Path Description
GET/api/me/tokensList your tokens
POST/api/me/tokensCreate a new token
DELETE/api/me/tokens/{id}Revoke a token

System

Method Path Description
GET/api/healthHealth check (deep when authenticated)
GET/api/system/statusSystem status (admin only)
GET/api/auth/statusAuth status check
GET/metricsPrometheus metrics
